## 4. Architecture & Design

### Native Wrapper (Android)
```
MainActivity.java
    ↓ (extends BridgeActivity)
    ↓
Capacitor Bridge
    ↓
WebView (Chrome WebView)
    ↓
LIFEHUB Web App (index.html + css + js)
```

### Data Flow
1. User interaction in Android UI
2. Capacitor WebView handles interaction
3. JavaScript application (app.js) processes action
4. IndexedDB stores data in app-private storage
5. Service worker caches static assets
6. Back button calls JavaScript handler in app.js
7. Handler manages navigation or closes modals

### Offline Architecture
```
Service Worker (cache-first strategy)
    ↓
Cache Storage (lifehub-v7)
    ↓
App Shell Assets (HTML, CSS, JS)
    ↓
IndexedDB Database (lifehub records)
    ↓
Works Completely Offline
```

## 7. Web Assets Synchronization

### How It Works
1. Source files maintained in repository root (index.html, css/, js/)
2. `www/` directory is production-ready copy for Capacitor
3. `npx cap sync` copies web assets to Android project
4. Android project loads from `android/app/src/main/assets/public/`

### Build Workflow
```
Source (root)
    ↓
Copy to www/
    ↓
npx cap sync
    ↓
Android assets/public/
    ↓
Android APK (embedded)
```

### Update Flow
When making web app changes:
```bash
# 1. Make changes to index.html, css/, js/
# 2. Copy to www/
cp index.html service-worker.js manifest.webmanifest www/
cp -r css js www/
# 3. Sync with Android
npx cap sync android
# 4. Rebuild APK
cd android && ./gradlew assembleDebug
```

## 10. Android Back Button Implementation

### Behavior Flow
```
User presses Android back button
    ↓
MainActivity.onBackPressed() called
    ↓
Calls window.lifehubHandleBackButton() via JavaScript bridge
    ↓
JavaScript handler in app.js executes:
    1. Is modal open? → Close it → Return "handled"
    2. Is nav open? → Close it → Return "handled"
    3. Is not on dashboard? → Navigate to dashboard → Return "handled"
    4. On dashboard? → Return null (let Android handle exit)
```

### Handler Location
- **File:** `js/app.js`
- **Function:** `window.lifehubHandleBackButton()`
- **Called by:** `MainActivity.java` via JavaScript bridge

### Customization
To modify back button behavior, edit `window.lifehubHandleBackButton()` in `js/app.js`:

```javascript
window.lifehubHandleBackButton = function() {
  // Add custom logic here
  // Return "handled" to prevent default Android behavior
  // Return null to let Android handle it (exits app)
};
```

## 11. Next Steps for Android Building

### On a Machine with Build Tools

1. **Install prerequisites:**
   ```bash
   # Windows: Use Android Studio installer
   # macOS: brew install android-sdk gradle openjdk11
   # Linux: apt-get install android-sdk gradle openjdk-11-jdk-headless
   ```

2. **Set environment variables:**
   - Set `JAVA_HOME` to JDK installation
   - Set `ANDROID_HOME` to Android SDK location

3. **Build the APK:**
   ```bash
   cd path/to/lifehub
   npm install
   cp index.html service-worker.js manifest.webmanifest www/
   cp -r css js www/
   npx cap sync android
   cd android && ./gradlew assembleDebug
   ```

4. **Install on device/emulator:**
   ```bash
   adb install app/build/outputs/apk/debug/app-debug.apk
   ```

5. **Or use Android Studio:**
   ```bash
   npx cap open android
   ```
   Then: Run → Run 'app' (Shift+F10)

## 15. Troubleshooting Guide

### "Android SDK not found"
**Solution:** Install Android Studio, run SDK Manager, install Build Tools 34 and Platform API 34.

### "JAVA_HOME not set"
**Solution:** 
```bash
# Windows (PowerShell)
$env:JAVA_HOME = "C:\Program Files\Java\jdk-11"

# macOS/Linux
export JAVA_HOME=/path/to/jdk
```

### "Build fails with gradle error"
**Solution:**
```bash
cd android
./gradlew clean
./gradlew assembleDebug  # Clean and rebuild
```

### "APK not found after build"
**Location:** `android/app/build/outputs/apk/debug/app-debug.apk`

### "App crashes on Android"
**Debugging:**
```bash
adb logcat -s lifehub    # View app logs
adb shell dumpsys meminfo com.raizen.lifehub  # Memory info
```

See ANDROID-BUILD.md for comprehensive troubleshooting.
